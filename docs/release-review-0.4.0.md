# 0.4.0 发布前代码审查与验证

审查日期：2026-09-23。范围包括规则、战役、存储、页面路由、Textual/SDL 适配、源码与冻结程序的一致性，以及 Windows/macOS/Linux 构建发布。保留已有规则与视觉设计，不将拆文件或提高抽象层数本身视为改进。

## 已修复的问题

| 原实现问题 | 修复与验证 |
| --- | --- |
| 编辑器切图、保存、导入、删除时临时设置 `page = "home"`，以绕过旧表单回写 | 路由显式支持是否捕获表单；地图选择先验证目标存在再提交状态。UI 回归验证新地图字段不被旧输入覆盖，目标丢失时保留当前地图 |
| 重开后调用路由，可能将上一局尚未结算的 `dt` 扣在重置后的棋盘上 | 替换前结算旧局，共用 `enter_game()` 建立新计时及展示边界。注入 17.5 秒未消费时间，验证新建与重开后仍为完整 240 秒，初始存档一致 |
| `GenerateConfig` 缺少直接调用时的类型校验，JSON 导入另有重复校验 | 参数类型、有限值和范围归模型自身负责，存储只做结构与错误转换。覆盖布尔值、浮点长度、字符串长度、NaN 和超大整数 |
| 超大 JSON 整数可能在 `math.isfinite` 中抛出未转换的溢出异常 | 共用数值校验拒绝不能表示为运行时有限数的输入；验证设置和成绩载入回退，并保留原文件 |
| Textual 私有 API 分散在应用及 SDL 模块，控件反向引用宿主渲染函数 | 将合成、字符绘制、事件坐标、取消指针与框架生命周期适配集中到 `textual_bridge.py`，控件不再引用 SDL 宿主；保留现有导出兼容调用方 |
| SDL 宿主直接理解 `app.store.settings`，启动或应用任务异常可能跳过清理 | 宿主只读取 `DisplayPreferences`；清理放入嵌套 `finally`，覆盖窗口初始化与异步应用失败两条路径 |
| 版本、分辨率和项目链接有多处维护点，虚拟环境元数据仍可能指向旧路径 | 版本动态生成包元数据；统一显示预设和项目链接；构建拒绝源码版本、安装元数据和标签不一致 |
| 工作流只提供 ZIP，没有安装程序和 Release 阶段 | 独立原生矩阵生成 Windows Setup、两种 Mac 架构的 PKG/DMG 和 Linux ZIP；安装后重新验证，再核对完整矩阵和 GitHub 端哈希后公开 |
| 旧测试报告可能被误用，发布文件缺少版本与架构约束 | 测试前移除对应旧报告，资产名包含版本和架构；发布回归验证缺平台、混提交、错误版本、脏工作区、文件变化和安装验证失败均被拒绝 |
| GitHub 按标签查询接口不返回草稿，首次上传后无法读取资产进行校验 | 使用包含草稿的分页 Release 列表；加入新建、草稿续传、权限错误和上传哈希异常回归。独立发布工作流可复用成功的原生作业，按原始标签源码再次验证产物，不移动标签或重建安装包 |

## 验证方式

```powershell
.\.venv\Scripts\python.exe -m ruff check src tools tests run.py
.\.venv\Scripts\python.exe -m pytest -q --junitxml=build/reports/pytest.xml
.\.venv\Scripts\python.exe tools/build.py
.\.venv\Scripts\python.exe tools/verify_native.py --output output/native-release-040
```

本机 Windows 11 / Python 3.13.5 验证结果：静态检查通过；399 项开发测试与 42 个子测试全部通过；源码与 Windows 冻结程序的共享套件均为 33/33，通过相同测试 ID 门禁。报告分别保存在 `build/reports/pytest.xml`、`source.json` 和 `frozen.json`。

`output/native-release-040/report.json` 记录三档真实 Windows 窗口启动、截图与零退出码；每档检查 72 个原生裁切边界采样点，实体音量 65→70→65、单色模式往返和最小化恢复检查通过。关机耗时约 1.31 秒。拖动坐标由脚本注入真实 SDL 宿主，不是人工鼠标验收。已查看最终 1024×768 内屏截图，布局、字体与 CRT 外壳保持完整。

已有 CRT 基线为 369 项开发测试和 33 项共享测试，详见 [基线记录](verification.md)。本次增加参数、计时、页面状态、资源清理与发布门禁回归。GitHub 上实际发布的二进制由各原生 runner 重新构建，最终跨平台结果以 Release 随附的清单和验证归档为准。

v0.4.0 标签对应的四个平台均通过 399 项开发测试与 42 个子测试，以及源码、冻结程序和安装后共享套件。随后修复的发布器额外增加 16 项回归，`tests/test_build_release.py` 合计 29 项通过；该修复只影响发布工具，安装包仍来自原始标签提交。

原生 CI 将开发测试、源码/冻结程序测试、安装后测试与正常窗口启动分别记录，不能用单个绿色步骤替代其他验证。Windows 另外验证覆盖安装、卸载和玩家数据保留；PKG 固定安装到 Applications，不因同标识的构建目录应用而重定位；DMG 保留应用内符号链接并检查 ad-hoc 签名；Linux 使用 Xvfb 启动解压后的程序。

## 保留的边界

`ArrowApp` 仍负责应用级服务组合、路由和游戏协调；页面及控件依赖明确的应用状态是当前规模下的直接组合，并未引入事件总线或通用仓储。Textual 6.12 的私有接口已集中，但仍属于需要随框架版本升级验证的依赖。pygame-ce 的 `Window.from_display_module` 仍有弃用提示，本次固定 2.5.8 并验证既有窗口接口，没有在发布前替换整套窗口 API。

Windows 未做发布者代码签名，macOS 只有 ad-hoc 签名且没有 Apple 公证。CI 使用 dummy 音频，Linux 使用虚拟显示；对应 runner 的自动验证不代表所有系统版本或硬件的人工实机验收。相关安装步骤和证据文件见 [构建说明](build.md)。
