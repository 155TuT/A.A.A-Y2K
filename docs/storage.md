# 设置、存档与成就

数据由 `storage.GameStore` 独立管理。默认目录使用
`platformdirs.user_data_dir("ArrowAfterArrowY2K", appauthor=False)`；
Windows 通常为 `%LOCALAPPDATA%/ArrowAfterArrowY2K`，不依赖安装目录或当前工作目录。
测试传入 `GameStore(temp_directory)` 隔离真实数据。

- `runtime.log`：仅无控制台启动时承接框架诊断，源码与冻结自测使用隔离内存日志。
- `settings.json`：自动保存开关、1–60 分钟保存间隔（默认 3 分钟）、总音量、音效音量、
  静音、分辨率与减少动画。
- `profile.json`：已解锁模式、成功移除总数、当前/最高连胜、无尽最快用时、
  地图编辑记录、成就 ID、引导完成状态与已结算关卡 ID。
- `slots/slot-0.json`：唯一自动槽；`slot-1.json` 至 `slot-4.json` 为四个手动槽。
- `custom_maps/<uuid>.json`：玩家自定义地图；内置模板来自关卡目录，不在这里保存，也不能通过此 API 删除。

`GameStore` 本身没有定时器、退出钩子或隐藏自动保存。应用负责只在开启自动保存时
调用 `save_slot(0, run)`；四个手动槽由明确操作保存。界面可通过 `slots()`
取得固定长度 5 的摘要列表，空槽为 `None`。存档写入本地时区的 ISO 8601 时间。
`save_slot` / `load_slot` 直接调用 `GameRun.to_dict/from_dict`，不另写游戏序列化逻辑，
因此剩余箭头、生命、关号、种子、计时与其他规则状态以引擎快照为准。

每次写入先在目标目录建立独立临时文件，写完并 `fsync` 后用 `os.replace` 替换。
失败时旧文件仍在；能清理的临时文件会清理。JSON 使用显式版本 1。
设置或玩家记录损坏时使用默认值启动，同时把原因加入 `store.warnings`，
不在读取时改写损坏文件。显式读写错误抛出可直接展示的 `DomainStorageError`；
槽和地图列表会跳过损坏项并记录警告。调用者应展示警告，避免把损坏文件误当作正常空槽。

自定义地图包含名称、难度、格子集合与完整生成参数，导入/导出复用同一数据格式。
导入一律分配新 UUID，避免覆盖现有同 ID 地图；更新已有地图显式传入 `map_id`。
删除 API 仅接收本模块格式的 UUID，不接收文件路径或模板名称。

`achievements.AchievementService` 只修改传入的 `Profile`，
由应用统一 `save_profile()`。调用返回本次新取得的成就列表供短暂通知使用：

- 简单模式“新手上路”初始已获得，不重复弹出通知。
- 正式关卡通过第 3 / 10 / 50 关，分别解锁中等 / 困难 / 无尽模式。
  这些是完成关号，不是新模式的起始关号；各新模式均从第 1 关开始。
- 累计成功移除 100 / 500 / 1,000 / 100,000 支箭头分别获得成就；碰撞不计数。
- 正式关卡连胜 10 / 50 / 100 / 500 次分别获得成就，失败重置当前连胜而保留最高连胜。
- 首次实际修改画布或成功保存自定义地图记录地图编辑成就；无尽首次完成获成就，并持续保留最快完成用时。

自定义地图计入箭头累计与地图编辑记录，但不解锁正式模式、不累计正式连胜。
无尽使用专用结算。应用应只在无尽胜利时调用 `record_endless(seconds)`。
每次正式通关按 `GameRun.completion_id` 持久去重；
读回已通关存档不会再次增加连胜或重放成就通知。失败结算由应用在正式局失败时调用。

旧版 demo 导出的 schema_version=1、cells/generation 格式仍可导入。
旧格式没有地图名称或难度，因此使用文件名作为名称、easy 作为编辑难度，并分配新 ID；
再次导出时使用包含名称与难度的新格式。
无控制台的 Windows 程序会将缺失的 stdout/stderr 及其原始流接到同一数据目录中的
runtime.log；已有控制台流不被替换。源码/二进制 --self-test 使用内存诊断流并把日志
写入指定测试报告，始终先于运行日志初始化，不因此访问真实玩家目录。
